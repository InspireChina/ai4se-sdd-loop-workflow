## 计划正文结构

正文按版块组织。只输出上面角色里列出的版块，没列出的版块不要补。每个版块内部按下列小节顺序写；版块内不涉及的小节保留标题并写「无」或「不涉及」，不得省略。

### 版块 A：后端实现计划（仅当后端相关时输出）

#### A1. 工程实现结构
- 仓库 / 服务 / 模块划分（本次新增或改动的服务/模块，落到具体目录）
- 包结构（新增包、改动包的层级与职责）
- 分层调用约束（哪层可调哪层、禁止反向依赖等；与仓库现有分层一致）

#### A2. 详细模型与数据设计
- **新增表**：表名、字段、类型、索引、约束；不涉及则写「无」
- **已有表更新**：表名、新增/修改字段、迁移说明；不涉及则写「无」
- 关键实体关系（必要时附简短 ER 说明）

#### A3. 接口清单
按 `method + path + 描述 + 入参 + 出参` 列出，并分三类、分对内/对外：
- **新增 API**：本次新增的接口
- **已有 API 修改**：改动现有接口（标注改动点：入参/出参/行为）
- **完全复用的 API**：本次依赖但不改动的现有接口
- **对内**（本服务/本仓库内部调用）与 **对外**（外部依赖、第三方、跨服务契约）分开列

#### A4. 消息与事件契约
- 新增/修改的消息主题、事件名、payload 结构、生产方/消费方
- 不涉及则写「无」

#### A5. 核心状态机与流程图
- 涉及状态流转的核心对象：用 mermaid 画状态机（`stateDiagram-v2`）
- 核心业务流程：用 mermaid 画流程图（`flowchart`）
- 不涉及状态机则写「无」，但只要有流程就画 mermaid

#### A6. 核心业务规则与具体实现
本节只写核心逻辑与实现，只列实际用到的：
- **算法**：核心算法、计算逻辑、排序/匹配/推荐/分摊等（写明落点：哪个模块/类负责）
- **外部依赖详细契约及应用场景**：调用方、被调方、契约内容、在哪个场景使用
- **涉及的表与字段及业务含义**：只列本次实际读写的表与字段
- **复用的代码逻辑**：复用的是哪段既有逻辑、改动点是什么、改了什么
- 与需求验收标准的对应关系

#### A7. 新增或修改的配置
- 配置项名、含义、默认值、影响范围；不涉及则写「无」

#### A8. 数据迁移与初始化方案
- 存量数据迁移步骤、初始化数据、回滚方案；不涉及则写「无」

#### A9. 并发与一致性方案
- 分布式锁、幂等、事务边界、数据一致性策略；不涉及则写「无」

#### A10. 性能与容量方案
- 缓存、限流、批量、异步、容量预估等；不涉及则写「无」

#### A11. 安全与权限
- 鉴权方式、数据权限、敏感数据保护、审计等；不涉及则写「无」

### 版块 B：前端实现计划（仅当前端相关时输出）

#### B1. 工程实现结构
- 目录 / 模块划分（本次新增或改动的页面/组件/工具目录，落到具体路径）
- 路由结构（新增/改动路由、路由守卫、懒加载策略；与仓库现有路由约定一致）

#### B2. 页面与路由
- 涉及的页面清单（页面名、路径、职责、入口来源）
- 路由变更（新增/修改/删除的路由及其跳转关系）

#### B3. 组件清单
按 `组件名 + 类型(新增/修改/复用) + 职责 + props + emits/事件` 列出：
- **新增组件**、**已有组件修改**（标注改动点）、**完全复用的组件**

#### B4. 状态管理
- 全局状态变更：新增/修改的 state、getter、action；不涉及则写「无」
- 页面级/局部状态关键点

#### B5. 接口契约（与后端联调）
- 前端调用的后端 API：`method + path + 触发场景 + 入参 + 期望出参 + 错误处理`
- 若后端 API 本次同步新增/改动，标注「需与后端版块 A3 对齐」
- 不涉及则写「无」

#### B6. 核心交互流程
- 关键用户操作流程用 mermaid 画流程图，含加载/成功/失败/空态分支
- 不涉及则写「无」，但只要有交互流程就画 mermaid

#### B7. 核心业务规则与具体实现
只列实际用到的：核心计算与校验及落点、第三方 SDK 契约与场景、实际使用的字段与业务含义、复用的既有逻辑与改动点、与验收标准的对应关系。后端 API 契约已在 B5 列出的不要重复。

#### B8. UI 规则与具体实现
- 表单校验、loading/empty/error、关键交互反馈

#### B9. 新增或修改的配置
